# 施設・町名の写真（探検の目印）

図鑑の詳細とクイズの解説には、実際に探検するときの目印になる写真を 1 枚ずつ載せられます。
写真は任意で、ない項目は今までどおり文章だけで表示します。

## 方針

- **軽量第一**: 1 枚あたり **80KB 以下、幅 640px 以下の WebP**。アプリ全体（JS gzip 148KB・地図 44KB）とのバランスを崩さない。
  写真 57 枚をすべて入れても合計 4.5MB 以下で、しかも必要なときにしか読み込まない。
- **必要なときだけ読み込む**: `loading="lazy"` / `decoding="async"`。未発見の項目や画面外の写真は通信しない。
- **レイアウトを動かさない**: `width` / `height` を実寸で指定し、読み込み前から場所を確保する（CLS 0 を維持）。
- **SVG も使える**: 写真の代わりにイラスト（SVG）を置いてもよい。SVG は変換せずそのままコピーする。
  地図・アイコンは引き続き SVG で、写真だけをラスタ（WebP）にする。
- **メタデータは削除**: 変換時に EXIF（撮影場所の GPS、機種名など）をすべて取り除く。

## 使ってよい写真

1. **自分で撮った写真**（推奨）。
   - 公道など、誰でも入れる場所から撮る。敷地内や校舎内の撮影は施設の許可を得る。
   - 人の顔、車のナンバー、表札、個人の家が主役にならないように。子どもが写ったものは使わない。
   - 建物の外観・門・看板など、現地で「ここだ」とわかる構図にする。
2. **利用条件が明示された写真**（CC BY など）。`credit` / `license` / `sourceUrl` を必ず記録する。
3. 鎌ケ谷市公式サイトや学校ホームページの写真は、**利用許諾を得てから**。無断転載はしない。

迷ったら入れない。写真がなくてもゲームは成立します。

## 追加のしかた

1. 元の写真を `data/photos/<項目ID>.jpg`（png / heic / webp / svg も可）に置く。`data/photos/` は Git 管理外です。
   項目 ID は `src/data/*.ts` の `id`（例: `library-main`、`es-kamagaya`、`town-0300`）。
2. 変換する。

   ```bash
   npm run photos:optimize
   ```

   1 枚だけなら `node scripts/optimize-photos.mjs <入力画像> <項目ID>`。
   `public/images/entries/<項目ID>.webp` ができて、貼り付け用の `photo:` の雛形が表示されます。
   80KB を超えるときは自動で品質を下げます。それでも超える場合は、被写体を絞ってトリミングしてから再実行してください。
3. 表示された雛形を `src/data/*.ts` の該当項目に貼り、`alt` / `credit` / `license`（必要なら `sourceUrl` / `takenAt`）を埋める。

   ```ts
   photo: {
     src: 'images/entries/library-main.webp',
     alt: '図書館本館の正面入口。白い建物に「鎌ケ谷市立図書館」の看板',
     width: 640,
     height: 480,
     credit: '撮影: （名前）',
     license: '撮影者の許諾',
     takenAt: '2026-10-16',
   },
   ```

4. テストで確認する（ファイルの有無、80KB 以下、幅 640px 以下、width/height が実寸と一致、alt/credit/license の記入）。

   ```bash
   npm test
   ```

## 表示される場所

- 図鑑の詳細（`EntryDetail`）: 地図の下に「めじるし（写真）」として実寸比で表示。**発見済みの項目だけ**。
- クイズの解説（`FeedbackCard`）: 正解・不正解の表示の下に高さ固定の帯で表示。
- どちらもクレジットと利用条件を写真の下に表示します。読み込みに失敗した写真は表示しません。
